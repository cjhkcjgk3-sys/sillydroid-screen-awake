# 酒馆屏幕常亮与任务媒体保活

SillyTavern 前端扩展，版本 1.4.0。前台防止无人操作时熄屏；任务期间提前启动本地循环视频和可选静音音频，切换到其他 APP 后继续保留媒体，尝试让内嵌网页持续处理结果和启动下一轮。

后台运行效果取决于 Android、APP 宿主及 WebView/GeckoView 内核。此扩展提供媒体保活策略，无法授予网页后台执行权限。静音音频也不保证获得浏览器的有声媒体豁免。需以手机实际发出后续轮次请求为验收依据。

## 安装和使用

在酒馆扩展管理页从 URL 安装：

```text
https://github.com/cjhkcjgk3-sys/sillydroid-screen-awake.git
```

刷新页面，在扩展设置中打开“保持屏幕常亮”。总开关默认关闭，旧版本的设置会保留。开启后，以下两项默认勾选，可分别关闭作对照：

- **任务期间持续播放视频**：整个任务持有保活期间，前后台都保留视频。
- **同时播放静音音频辅助保活**：播放本地生成的一秒静音 WAV，无网络音源、无麦克风权限、不播放提示音。

请在前台开启插件并启动任务，确认自检显示媒体已播放，再切换 APP。播放被内核拒绝时，返回前台触摸或重新打开总开关可以重试。总开关关闭、扩展禁用都会停止媒体并清理资源。

## 运行规则

| 场景 | 行为 |
|---|---|
| 前台，无任务 | 优先屏幕唤醒锁，失败才用视频防熄屏 |
| 前台，任务运行 | 立即启动任务视频与可选音频；屏幕唤醒锁成功也保留视频 |
| 切后台，任务运行 | 保留媒体，释放仅供前台使用的屏幕唤醒锁 |
| 单轮生成结束，整个任务仍运行 | 继续保留媒体，覆盖保存、处理、重试与下一轮之间的空隙 |
| 暂时断网或等待重试 | 保留任务持有状态，不按离线状态或固定时长推断失败 |
| 整个任务完成、明确暂停或停止 | 释放对应任务持有状态；后台最后一个持有者释放后停止媒体；前台恢复普通常亮规则 |
| 页面离开/刷新、禁用或关闭总开关 | 停止媒体、释放相关资源 |

任务以独立持有者集合管理；多个任务重叠时，最后一个释放才结束任务保活。取消了原有“单次生成超过 20 分钟自动释放”的规则。若调用方异常退出却未发结束信号，需手动关闭总开关；长时间没有回调不能用来判断任务真的失败。

媒体被内核暂停后，五秒自检会尝试恢复；播放失败带三十秒退避。网页自身被冻结时，自检也会暂停，因此自检不能代替宿主后台支持。界面“播放中”表示媒体元素报告的状态，实际进展可查看诊断中的时间戳。

## 自动任务联动

已有 Novel-Auto-Generator 的 `#nag-status.running` 徽章继续兼容。发现徽章后用属性观察器及时感知状态，两秒轮询兜底检查徽章的出现或替换。徽章离开 running 会释放该任务持有；重试期间调用方应保持 running。

其他插件可以沿用显式接口，建议覆盖整个自动任务，而非每轮单独持有：

```js
const keeper = globalThis.SillyDroidScreenAwake;
keeper?.hold('my-batch');
try {
    // 执行整个批次：多轮生成、结果处理、必要的网络重试。
} finally {
    // 正常完成、用户停止、或重试耗尽后，均释放本批次持有。
    keeper?.release('my-batch');
}
```

`hold()` 会立即启动媒体准备，返回值仍是布尔值，不表示播放器已经就绪。第一次视频准备包含约 300 毫秒本地录制，请确认播放状态后再切后台。显式接口与酒馆单次生成事件各自持有；手动停止整个任务时，调用方也应取消尚未结束的生成。

酒馆现有的 `generation_started` / `generation_ended` / `generation_stopped` 监听继续兼容；禁用时成对解绑。没有修改其他任务插件或酒馆核心，也没有自动判断网络错误的逻辑。任务最终失败须由任务方的状态或 release 信号告知。

诊断不包含聊天正文或密钥：

```js
globalThis.SillyDroidScreenAwake?.getDiagnostics();
// visibility、holds、videoRequested、videoPaused、videoTime、
// lastVideoProgressAt、lastVideoError、audioPaused、lastAudioError
```

## 原有阅读功能

- 页面压暗 0–80%，遮罩不拦截操作；OLED 屏幕上可降低发光功耗。
- 无操作 N 分钟自动放开，0 为不自动放开；任务持有期间不触发空闲休眠。
- 任务完成时若前台仍在阅读，按最近操作时间恢复普通空闲策略。
- 屏幕唤醒锁通常要求 HTTPS 或 localhost/127.0.0.1 安全上下文；不可用时尝试视频。
- 保持屏幕亮起会增加耗电。音频辅助可能占用媒体通道、影响其他音乐 APP 的音频焦点；可单独关闭。

视频为现场录制的 16×16 无声 WebM，在页面以 2×2 像素显示；音频为 8 kHz、单声道、16 位 PCM 全零静音 WAV（约 16 KB）。所有媒体保留在本地 Blob URL，不请求外部资源。没有添加原生后台服务、Media Session 状态伪装或虚假播放通知。

## 验证

离线回归：

```sh
node --test tests/background-task.test.cjs
node --input-type=module --check < index.js
```

测试使用浏览器能力替身，验证任务状态、前后台切换、两轮之间持有、关闭清理和异步竞态，不证明手机内核的实际后台待遇。

手机验收建议用同一任务分别测试：前台基准、关闭后台媒体、只开视频、视频加静音音频。每组连续三轮，切其他 APP 后十分钟不返回，以服务日志确认后两轮请求在后台期间已经发出。再单独测试锁屏。检查任务完成、暂停、停止和最终失败后媒体释放，以及暂时断网重试时仍保留。记录 APP 版本、Android 版本和内核版本；若媒体仍播放而后续请求停住，应继续排查宿主后台调度。

本版本尚未在目标手机实测。验收失败可关闭两个新选项恢复原有前台策略，或回退到 1.3.0 对应提交 `e7ea70ffdbbefbdcb3e911aa187414b5dc8b472b`。
