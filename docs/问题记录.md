- 格式：[小问题](https://github.com/cjhkcjgk3-sys/ai-dev-lessons/blob/main/模板/问题记录-小.md)写原因、解决、状态；[大问题](https://github.com/cjhkcjgk3-sys/ai-dev-lessons/blob/main/模板/问题记录-大.md)写出错模型、发现者、状态、现象、原因、证据、解决方法、预防措施、归类。
- 状态只用：未解决／已修未实机验证／已实机验证。拿不准是否通用的，标“可能通用”。
- 新记录追加在下方，不删旧记录。

## 记录

### [小] 唤醒锁被系统收回后不再申请、快速切换前后台时状态显示错误（不追究，1.1.0 前）
原因：系统在可见状态下收回唤醒锁后没有重试；过期的 release 事件把“已开启”覆盖成警告；`getContext()` 暂时不可用就永久放弃挂载。
解决：[47658ee](https://github.com/cjhkcjgk3-sys/sillydroid-screen-awake/commit/47658ee)（1.1.0）加指数退避重试、忽略过期事件、改为继续观察重试。
状态：已修未实机验证

### [小] 事件丢失时保亮状态不对（不追究，1.3.0 前）
原因：唤醒锁被静默回收但 release 事件没送达、页面隐藏但 `visibilitychange` 没触发等情况，只靠事件驱动处理不到。
解决：[08eb210](https://github.com/cjhkcjgk3-sys/sillydroid-screen-awake/commit/08eb210)（1.3.0）每 5 秒对账一次，不一致就纠正，连续失败有 30 秒冷却。
状态：已修未实机验证

### [小] 任务期间切到后台的媒体保活未在目标手机验证（2026-11 起）
原因：[a0e91e6](https://github.com/cjhkcjgk3-sys/sillydroid-screen-awake/commit/a0e91e6)（1.4.0）提交说明写明“target-phone background behavior remains pending real-device verification”；[163ff99](https://github.com/cjhkcjgk3-sys/sillydroid-screen-awake/commit/163ff99)（1.4.1）继续增强。
解决：待用户在目标手机上验证。
状态：未解决
